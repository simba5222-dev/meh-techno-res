# Служба механиков — заметки по проекту

Внутренняя система постановки и контроля задач для отдела механизации.
Живёт на `http://meh.techno-res.ru/`, хостинг Timeweb, аккаунт `c73065`.

## Стек и ограничения среды

- PHP 8.2, MySQL 5.7 (Percona), nginx + Apache, **shared-хостинг**
- Node.js, Python, Docker, composer на хостинге **недоступны** — только чистый PHP и загрузка файлов
- Сборки нет: что лежит в `public_html`, то и работает
- База `c73065_meh`, доступ только с localhost, реквизиты в `config.php` (в репозиторий не коммитить)
- SSL пока не выпущен — сайт работает по `http://`. Это блокирует вебхуки для будущего бота

## Роли

| Роль в БД  | Кто это            | Доступ |
|------------|--------------------|--------|
| `admin`    | главный механик    | всё |
| `mechanic` | механик участка    | свои задачи, свой отчёт, просмотр техники |
| `fitter`   | слесарь            | **входа на сайт нет**, `can_login = 0`, `username`/`password_hash` — NULL |
| `manager`  | менеджер           | только просмотр техники |

Цепочка работ: главный механик ставит задачу на объект и назначает механика
(`tasks.assignee_id`) → механик распределяет её на слесарей (`task_assignees`)
либо разбивает на подзадачи через `tasks.parent_id`.

Слесари не логинятся принципиально: они не пользуются компьютером. Отметки за них
ставит механик, в перспективе — бот в мессенджере MAX.

## Схема базы

Все ключи `INT(10) UNSIGNED` — при добавлении внешних ключей несовпадения типов не будет.

- `users` — + `can_login`, `max_user_id` (зарезервировано под MAX-бота)
- `equipment` — парк техники, `object_id` (необязательная привязка), мягкое удаление через `is_active`
- `objects` — участки; не удаляются, а отключаются (`is_active`), чтобы не терять историю
- `user_objects` — закрепление людей за объектами, многие-ко-многим
- `tasks` — `object_id`, `parent_id`, `assignee_id` (ответственный механик), `status` (VARCHAR, код из `task_statuses`)
- `task_assignees` — слесари на задаче, много на одну
- `task_statuses` — справочник статусов, см. ниже
- `task_history`, `task_photos` — история изменений и фотоотчёты
- `daily_reports` — ежедневные отметки; `source` (`self`/`mechanic`/`max_bot`), `recorded_by`

Актуальную схему снять так:
`mysqldump --no-data -u c73065_meh -p c73065_meh > schema.sql`

## Статусы задач — ключевая механика

Статусы **не зашиты в код**, они строки в `task_statuses`. `tasks.status` хранит `code`.

У статуса есть:
- `sort_order` — порядок колонок на доске
- `is_initial` — в нём создаются новые задачи (должен быть ровно один активный)
- `is_final` — задача закрыта, не попадает в активные и не считается просроченной
- `writes_report` — при переходе пишется строка в ежедневный отчёт исполнителей
- `allow_admin` / `allow_mechanic` / `allow_fitter` — **кому разрешено переводить задачу в этот статус**

Отсюда важное следствие для любых доработок: **нельзя писать в коде `status = 'verified'`
или `IN ('new','rejected')`**. Для этого есть хелперы в `includes/functions.php`:

- `task_statuses_all()`, `task_status_get()`, `task_status_label()`, `task_status_style()`
- `task_status_initial()` — код стартового статуса
- `sql_not_final($alias)` / `sql_is_final($alias)` — готовые SQL-условия
- `statuses_allowed_for_role()`, `can_set_status()`
- `change_task_status()` — единая точка смены статуса: пишет историю, закрывает задачу, добавляет строку в отчёт. Используется и в `task_view.php`, и в AJAX-эндпоинте

## Соглашения в коде

- Вывод только через `e()`, запросы только подготовленные
- Формы защищены `csrf_field()` / `csrf_verify()`
- Сообщения пользователю через `flash()` + `redirect()`
- Комментарии и интерфейс на русском
- Правки статусов/ролей — через справочники, а не константы в коде

## Грабли, на которые уже наступили

1. **Кеш статики.** `style.css` и `app.js` подключаются с `?v=filemtime(...)`. Без этого браузеры держат старые версии сутками. При добавлении новых css/js делать так же.
2. **Перетаскивание карточек.** Карточка — ссылка, и браузер запускает своё перетаскивание ссылки, перехватывая жест. Лечится `-webkit-user-drag: none` и `user-select: none` в `board.css`. Если появятся новые интерактивные элементы внутри карточки — проверять это заново.
3. **Пустые колонки на доске.** Колонки должны быть одной высоты (`align-items: stretch`, `min-height`), иначе в пустую колонку некуда бросить карточку. Плюс в `app.js` есть поиск ближайшей колонки при промахе.
4. **Тач-устройства.** На ширине до 1050px колонки идут вертикально, перетаскивание конфликтует с прокруткой — там на карточках остаётся выпадающий список «перенести в…».
5. **Загрузка файлов через панель Timeweb** ставит права 600. Сайт при этом работает (PHP исполняется от владельца), но если появится что-то, читаемое другим пользователем, права придётся править.
6. **Редирект meh → ttrn** был локальным кешем браузера, не конфигурацией сервера. Привязка доменов в панели корректна.
