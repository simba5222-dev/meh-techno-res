# Хронология работ по системе задач для отдела механизации

Перенесено из проекта claude.ai «Отдел механизации» 16.09.2026. Документ отражает
состояние на 05.09.2026 — до переработки со справочником статусов, объектами и слесарями.

## Исходные данные

- Парк техники: более 50 единиц (по факту в базу завели 104)
- Структура: главный механик ставит задачи, линейные механики в полях выполняют, 10–30 пользователей
- Хостинг: hosting.timeweb.ru, классический shared (PHP, MySQL, SSH/FTP только для файлов;
  Node.js / Python / Docker не поддерживаются)
- Требование: онлайн-решение на своём хостинге, регистрация пользователей, учёт всего парка,
  постановка задач, в любой момент видно, кто чем занят

## Что рассматривали до своего приложения

Готовые SaaS-трекеры — Битрикс24, Kaiten, Weeek, Pyrus. У всех бесплатные тарифы обрубают
именно контроль выполнения при таком объёме задач (например, Битрикс24 free отключает
подтверждение/проверку задач после сотой). Затем обсуждали Telegram-бота как быстрый старт.
В итоге остановились на полноценном веб-сайте на собственном хостинге.

## Первая версия приложения (PHP 8 + MySQL)

Из-за типа хостинга сделали классическое веб-приложение на чистом PHP — разворачивается
загрузкой файлов по FTP, без сборки.

- Роли: главный механик (admin) и линейный механик (mechanic)
- Разделы: дашборд, задачи (канбан), техника (реестр + карточка с историей), пользователи
- Жизненный цикл задачи: Новая → Принята → В работе → Выполнена → Проверена, с возвратом
  на доработку и фотоотчётом на любом шаге
- История изменений и комментарии по каждой задаче, адаптивная вёрстка

Передано пользователю 05.09.2026 архивом `meh-tasks-system.zip` с инструкцией по развёртыванию.

## Реальный парк техники

Пользователь параллельно сделал свой прототип (папка GPT) с реальными данными. Из прототипа
взяли список техники — 104 единицы — и оформили как `seed_equipment.sql` для разового импорта
через phpMyAdmin сразу после `schema.sql`. Вёрстку прототипа не переносили.

## Развёртывание на meh.techno-res.ru

Timeweb, аккаунт c73065: создан поддомен, база `c73065_meh`, загружены файлы, настроен
`config.php`, импортированы `schema.sql` и `seed_equipment.sql`.

**Грабли:** при первом входе логин молча не срабатывал. Причина оказалась не в коде и не в
настройках сервера: в тестовом браузере лежала старая cookie `PHPSESSID`, привязанная к
домену шире поддомена — она перекрывала новую сессионную cookie, сервер каждый раз читал
старое, не залогиненное значение. После очистки конфликтующих cookie вход заработал.
Для обычных посетителей проблемы нет.

## Роль «менеджер», ежедневные отчёты, отчёты с CSV

- Новая роль `manager` в дополнение к `admin`/`mechanic`
- `report_today.php` — отметка присутствия и сводка за сегодня (у механика пункт «Мой отчёт»)
- `timesheet.php` — табель по сотрудникам за период
- `reports.php` — три среза (по механикам, по задачам, по технике) с выгрузкой в CSV
  (с BOM, чтобы кириллица корректно открывалась в Excel)
- Мягкое удаление техники вместо жёсткого

Миграция БД (роль `manager` + таблица `daily_reports`) — в `db-2026-09-05/migration_manager_reports.sql`.

**Грабли выкладки:** файлового доступа к продакшену тогда не было, файлы передавали через
веб-консоль SSH Timeweb чанками base64 по ~2900 байт с проверкой md5 после сборки каждого
файла. Обычная вставка больших файлов в терминал приводила к обрывам и потере символов —
один чанк однажды потерял 4 символа, поймали только сверкой контрольной суммы. Размер чанка
потом снизили до 2000 байт.

## Адаптация под планшеты

Механики работают в полях с разных устройств. Переработали `style.css`:

- **Найдена скрытая проблема:** в диапазоне ширин ~721–1050px (большинство планшетов в обеих
  ориентациях) пункты меню слева выглядели пустыми кнопками — `font-size: 0` без замены на
  иконку. Навигация фактически была не видна. Исправлено объединением двух медиа-запросов
  в один (`max-width: 1050px`) с горизонтальным меню и видимыми подписями
- Тач-зоны кнопок, пунктов меню, переключателей статуса, чекбоксов, вкладок — минимум ~44px
- `touch-action: manipulation` — убирает задержку тапа и случайный двойной зум на iOS
- У всех полей ввода `font-size: 16px` — ниже этого Safari принудительно зумит страницу
- Канбан и таблицы: на планшетной ширине колонки выстраиваются вертикально,
  `-webkit-overflow-scrolling: touch` для таблиц, где горизонтальная прокрутка нужна

## Автоматическое попадание выполненных задач в отчёт

Когда линейный механик переводит задачу в «Выполнена», в той же транзакции в его отчёт за
сегодня добавляется строка вида:

`Задача #12 «Замена масляного фильтра» (INV-034 — Экскаватор JCB) — выполнена. <комментарий>`

Если отчёта за сегодня нет — создаётся с отметкой присутствия. Текст остаётся редактируемым.
Логика вынесена в `append_daily_report_note()` в `includes/functions.php`.
